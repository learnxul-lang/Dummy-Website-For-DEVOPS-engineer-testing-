# Candidate Instructions

## Scenario
You have joined a development team as a Junior DevOps Engineer. A small website exists, but the team needs a controlled Git/GitHub collaboration and deployment workflow.

## Objective
Demonstrate that you can manage the project through local version control, remote collaboration, branching, Pull Requests, synchronisation and automated deployment.

## Practical tasks
1. Obtain a local working copy of the supplied project.
2. Inspect the project and its version-control state.
3. Ensure environment configuration and other inappropriate local files cannot accidentally be published.
4. Establish a meaningful local project history.
5. Connect your local work to the assigned GitHub repository and publish the required work.
6. Perform new development on a separate feature branch rather than making the requested change directly on the production branch. **Feature branch names must follow the convention `feature-*`**, for example `feature-status`, `feature-release` or `feature-readme`.
7. Add a visible **System Status** section containing: **Application operational**.
8. Record the change with a meaningful history entry and publish the feature work.
9. Create a Pull Request with a useful description of the proposed change.
10. Review and integrate the approved work into the production branch.
11. Complete the remote-collaboration incident when it is issued by the assessor.
12. Deploy the production branch through Vercel.
13. Complete a second release that changes the visible version from **Version 1.0** to **Version 1.1**, using the collaboration workflow established during the assessment.
14. Demonstrate that the approved second release results in a new live deployment.

## Important
You are expected to determine the appropriate Git/GitHub commands and workflow yourself. The assessment instructions intentionally do not provide a command-by-command solution.
